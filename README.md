## 更新与边界

### 生图不局限于 SEO 维护

独立生图、海报、活动图、参考图编辑等任务，由当前 Codex 自动复用已配置的图片 API 或 O2 `gpt-image2`，按实际需求选择文生图/编辑；不要求先巡检店铺、不重复索要已有 Key。现有 SEO 通道的 `JD_LLM_API_KEY` 可在确认同一京东网关后仅对子进程映射为 `GPT_IMAGE2_API_KEY`，不打印或另存凭据，不改变用户指定服务。已有 O2 原生配置继续复用，缺少原生图片工具不代表不能生图。必须实际调用、核验并交付图片，真实权限或服务阻断如实说明，不假报成功。

### 能力集合，不是 Codex 的任务边界

插件的 Skill、CLI 和接口供当前 Codex 优先调用，不要求所有需求都套固定脚本。现成流程不覆盖时，Codex 应主动查找、组合其他已获准能力，在任务目录编写并验证辅助脚本，尽可能完成用户原目标；不要仅因“未收录”或某脚本失败就让用户找 caotong.888。

辅助取数、可靠分批和适配不必等待插件发布；不修改插件缓存或受保护核心，不绕过身份与具体写入确认，不重放未知写入，不把部分数据当全店。大店铺分页等新场景需同事本机验证真实接口和覆盖率，未验证不能声称已修复。与插件无关的独立任务不受本插件业务范围限制，但不得以此绕过产品门禁。

不要默认请求负责人远程接管，也不让用户来回传截图和命令。确需维护发布时，当前 Codex 先整理实际版本、失败阶段、最小复现、已尝试方案、必须发布的依据及未完成范围的脱敏摘要，让负责人无需从头排查；不自动发消息或预约远程。产品资格只提供最少资格信息。

## 已登录京ME却提示身份错误

不能把“未取得身份”直接解释成“同事没登录”。本次修订修复旧版将本机连接失败、超时、协议异常和网关换票失败统一报为 `ERP_NOT_LOGGED_IN` 的问题。本机官方十个候选端口并行检查，每个最多等待 5 秒，选取一个有效响应后取消其他检查；只有身份请求，绝不重试业务写入或变更公司安全策略。

请助手先执行 `node verify.mjs` 校验本下载目录，再运行 `node diagnose-identity.mjs`。这只校验本机身份，不安装、不登记插件、不执行店铺任务，也不查看名单。诊断成功后运行 `node install.mjs --check` 只核验本人插件资格，资格通过再按原安装请求执行 `node install.mjs`。

| 错误 | 含义与下一步 |
| --- | --- |
| `ERP_HIOFFICE_UNREACHABLE` | 当前 Codex 核对同机同用户、实际端口与执行环境，修复后回查，不反复登录。 |
| `ERP_HIOFFICE_TIMEOUT` | 当前 Codex 按阶段排查本机响应与网络耗时，修复后回查，不误报未登录。 |
| `ERP_HIOFFICE_ACCESS_DENIED` | 当前 Codex 核对实际访问身份与权限，带本人完成必要批准，不关闭防护或绕过策略。 |
| `ERP_HIOFFICE_PROTOCOL_ERROR` | 本机响应不符合协议。核对京ME版本及兼容性。 |
| `ERP_TOKEN_EXCHANGE_FAILED` | 当前 Codex 排查换票网络、本人会话与有效期，修复后重新验权，不重新开白。 |
| `ERP_IDENTITY_REJECTED` | 验票服务拒绝当前票据。核对票据有效性与服务状态后再判断是否需要重新登录。 |
| `ERP_NOT_ALLOWED` | 插件使用资格未通过，联系负责人 ERP：caotong.888 核对本人产品资格。 |
| `ERP_AUTH_UNAVAILABLE` / `ERP_AUTH_TIMEOUT` / `ERP_AUTH_RESPONSE_INVALID` | 按输出的失败阶段排查网络、服务响应或协议。 |

诊断只输出错误码、阶段、候选端口结果和中文建议，不输出票据、Cookie、密钥或网关响应正文。不要提供这些凭据，也不要把 `identityVerified=true` 当成插件已开通。
