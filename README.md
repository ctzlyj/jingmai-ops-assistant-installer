# 京麦运营助手（采销版） · ERP 安装入口

安装入口修订 0.4.1-bootstrap.1，配套完整插件 0.4.1。这个公开仓库只包含安装引导，不含可直接安装的插件或完整 Skill。请下载最新安装入口，不复用旧 v0.4.0 下载目录。

**全部 26 个 Skill 统一要求本人 ERP 产品授权：7 项定制业务、17 项官方京麦 CLI 能力、统一入口和安装引导。先验权，后领取并安装完整插件。** 未登录、未开通、已撤权或服务不可用时停止；不创建插件目录，不登记插件市场。管理员身份不等于产品使用资格。

## 同事安装

准备 Windows、Node.js 22.15+、Codex CLI、京东网络，并使用本人账号登录京ME/HiOffice。联系维护人开通“京麦运营助手（采销版）”；无需提供密码或票据。

下载本仓库 release 中的安装入口，解压后请 AI 助手读取 README 并执行：

```text
node install.mjs
```

也可把本仓库链接给助手，说：“请安装京麦运营助手，先验证我本人的 ERP 资格；没开通就停止，不要改用独立 Skill 绕过。不要执行商品操作。”

安装器通过固定授权服务领取带 SHA-256 的版本包，二次验权后安装到用户目录。每次使用任一能力仍须重新领取受保护说明；7 项定制业务的必需核心也在服务端逐次验权。不要使用 `codex plugin marketplace add` 直接安装这个公开仓库。

## 更新与边界

- 需要店铺数据却尚未完成京麦 CLI 登录时，助手会启动官方授权流程。你只需在独立窗口登录目标店铺、扫码或输入验证码并点击授权；助手自动等待和回查，不需要输入 Profile、AppKey、AppSecret 或“已授权”。不要把密码和验证码发给助手。ERP 插件资格与店铺登录是两件事。

- 从 0.4.1 起，新任务首次进入助手时由 Codex 统一检查更新；同核心、同主次版本且维护人明确标记兼容的补丁，可在业务开始前通过内置安装器更新。跨版本、未标记兼容、本地改动或未完成任务不自动切换。
- 更新成功后由 Codex 核验文件并提示新建对话；不需要采销敲命令，不自动重启或恢复业务。平台权限提示仍由本人确认。0.4.0 尚无内置更新器，给 Codex 发一次“帮我更新京麦运营助手”即可按本入口完成升级。
- 旧的完整源码或已下载内容不能远程收回；本插件的授权不能限制插件外独立合法使用官方 CLI。不要把已授权取得的包转发他人。
- ERP 资格不代替店铺 OAuth、业务权限、写入确认或模型费用授权。安装不自动巡检、改价、发品或执行历史任务。
- 旧 v0.3.1 完整分发已撤下；请勿使用旧安装方法。
- JoySpace 教程：https://joyspace.jd.com/pages/Fu3S4L71cjvSiyh56hF3 。教程权限由维护人自行设置。

## 已登录京ME却提示身份错误

不能把“未取得身份”直接解释成“同事没登录”。本次修订修复旧版将本机连接失败、超时、协议异常和网关换票失败统一报为 `ERP_NOT_LOGGED_IN` 的问题。本机官方十个候选端口并行检查，每个最多等待 5 秒，选取一个有效响应后取消其他检查；只有身份请求，绝不重试业务写入或变更公司安全策略。

请助手先执行 `node verify.mjs` 校验本下载目录，再运行 `node diagnose-identity.mjs`。这只校验本机身份，不安装、不登记插件、不执行店铺任务，也不查看名单。诊断成功后运行 `node install.mjs --check` 只核验本人插件资格，资格通过再按原安装请求执行 `node install.mjs`。

| 错误 | 含义与下一步 |
| --- | --- |
| `ERP_HIOFFICE_UNREACHABLE` | 无法连接本机京ME接口。核对同机、同用户环境与本机接口可达性；由IT检查，不反复登录。 |
| `ERP_HIOFFICE_TIMEOUT` | 本机身份接口响应超时。保留阶段信息，由维护人排查耗时。 |
| `ERP_HIOFFICE_ACCESS_DENIED` | 本机接口访问被拒绝。交IT核对，不关闭防护或擅自扩大权限。 |
| `ERP_HIOFFICE_PROTOCOL_ERROR` | 本机响应不符合协议。核对京ME版本及兼容性。 |
| `ERP_TOKEN_EXCHANGE_FAILED` | 本机响应已取得，但网关换票失败。交维护人排查换票，不重新开白。 |
| `ERP_IDENTITY_REJECTED` | 验票服务拒绝当前票据。核对票据有效性与服务状态后再判断是否需要重新登录。 |
| `ERP_NOT_ALLOWED` | 插件使用资格未通过，联系负责人核对本人 ERP。 |
| `ERP_AUTH_UNAVAILABLE` / `ERP_AUTH_TIMEOUT` / `ERP_AUTH_RESPONSE_INVALID` | 按输出的失败阶段排查网络、服务响应或协议。 |

诊断只输出错误码、阶段、候选端口结果和中文建议，不输出票据、Cookie、密钥或网关响应正文。不要提供这些凭据，也不要把 `identityVerified=true` 当成插件已开通。

0.4.1 完整包同步修复统一入口及七项定制 Skill 的身份模块，包含统一更新检查；升级仍须通过安装器领取新版，不直接编辑插件缓存。安装后由 Codex 运行插件根 `scripts/jingmai-update.mjs --check` 及 `scripts/jingmai-ready.mjs`，分别核验版本与实际入口。尚未复现的公司策略或客户端兼容问题仍需受影响电脑实际回读确认。
